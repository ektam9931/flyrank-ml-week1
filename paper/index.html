Predicting Content Performance Changes for Search Discoverability

A decision-support model for identifying content pages that may warrant review or refresh.

Author: Ekta Kumari

Abstract

This project asks whether historical search, traffic, engagement, and content signals can be used to predict changes in content clicks and prioritize pages for review. I framed the problem as a regression task where the target is the observed change in clicks between the latest 30-day period and the previous 30-day period. A Random Forest Regression model was evaluated using a client-grouped train-test split so that entire clients were held out from training. The leakage-audited model achieved an MAE of 1.478, RMSE of 7.048, and R² of 0.529, compared with a zero-change baseline MAE of 1.898 and RMSE of 10.267. The resulting predictions are used as directional decision-support signals for prioritizing pages for review rather than as guarantees of future performance or causal evidence about search algorithms.

1. Introduction / Problem Statement

Content teams often have more pages to monitor than they can manually review. A useful machine-learning system should therefore help prioritize pages for attention using measurable historical signals.

The research question for this capstone is:

Can historical content, search, traffic, and engagement signals help predict short-term changes in clicks and support a ranked content-review workflow?

The practical decision supported by this analysis is which pages deserve closer review or refresh attention, and which pages can instead be monitored or protected.

2. Data

The analysis uses the public-safe FlyRank ML Internship dataset release available through the internship workflow. The working dataset contains 30,000 anonymized content observations and 44 original columns.

The dataset includes anonymized content and client identifiers together with search-demand signals, competition indicators, content characteristics, historical impressions and clicks, sessions, engagement measures, content age, freshness indicators, CTR, average position, and trend information.

The target was constructed as:

click_change = clicks_last_30d − clicks_prev_30d

No client names, domains, URLs, private queries, credentials, or raw private exports are included in this paper.

The original dataset does not provide an observation date suitable for a chronological train-test split in this workflow. Therefore, the validation design uses grouped client-level separation rather than claiming time-aware validation.

3. Methodology

Target

The regression target is the observed change in clicks between the latest 30-day period and the previous 30-day period.

Features

The model uses numerical and categorical signals describing search demand, competition, content characteristics, historical traffic, impressions, engagement, content age, freshness, CTR, average position, and related performance indicators.

Validation design

A GroupShuffleSplit was used with client_id as the grouping variable. The split produced 23,837 training observations from 25 clients and 6,163 test observations from 7 held-out clients.

This design prevents observations belonging to the same client from appearing in both training and test sets. Because there is no suitable observation date in this dataset, the split is not described as time-aware.

Model

The final model is a Random Forest Regressor with 200 trees and a maximum depth of 12. Numerical features were median-imputed, while categorical features were imputed using the most frequent category and one-hot encoded.

Baseline

The baseline predicts zero change for every test observation. This represents the simple assumption that clicks will not change.

Leakage audit

The final feature set explicitly excludes the target and direct components used to calculate the target: click_change, clicks_last_30d, clicks_prev_30d, and clicks_90d. Trend fields used in the earlier workflow were also excluded from the audited feature set.

The leakage-audited Random Forest performs better than the zero-change baseline on all three reported metrics. Its MAE is lower than the baseline by approximately 22%, while RMSE is also substantially lower. The R² value of approximately 0.529 indicates that the model explains a meaningful portion of variation in the held-out test data under this validation design.

Interpretation: These are measured results on the selected held-out client groups. They should be interpreted as evidence of predictive usefulness within this dataset and validation setup, not as proof of causal impact.

5. Error Analysis

The model performs considerably better on typical observations than on extreme changes in clicks. The largest observed absolute prediction error was approximately 367.5 clicks.

This indicates that extreme positive or negative changes are difficult for the model to estimate accurately. The model should therefore be treated as a prioritization system rather than a precise forecasting instrument for every individual page.

Action playbook

  • Review / Refresh: prioritize pages with large predicted negative click changes for human review.
  • Monitor / Protect: pages with positive predicted changes can be monitored rather than immediately changed.
  • Validate before action: predictions should be checked against current page context and business priorities.
  • Do not infer causality: a high opportunity score does not prove that refreshing a page will cause clicks to increase.

8. Limitations & Honest Framing

  • The dataset does not provide a suitable observation date for a chronological validation split.
  • The grouped split tests generalization across held-out clients, not future performance over time.
  • The target measures observed click change and does not establish why the change occurred.
  • Feature importance describes model behavior and is not causal evidence.
  • The model struggles with extreme click changes.
  • The analysis cannot prove or disprove Google's ranking algorithm.
  • The recommendations are decision-support signals and require human review.

Therefore, the strongest defensible conclusion is that the leakage-audited Random Forest showed better predictive performance than the zero-change baseline under the selected grouped validation design and can be used as a directional prioritization tool.
